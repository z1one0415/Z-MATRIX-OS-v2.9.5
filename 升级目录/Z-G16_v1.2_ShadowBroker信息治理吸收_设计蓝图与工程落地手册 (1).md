# Z-G16 Physical Reality Layer v1.2
# ShadowBroker 信息治理与分析机制吸收｜设计蓝图 + 工程落地手册

> **系统**：Z-MATRIX-OS  
> **版本**：Z-G16 v1.2  
> **定位**：Event Intelligence Governance Layer  
> **执行对象**：OpenClaw 天师 / deepseek-v4-pro  
> **执行等级**：A+ 可落地工程说明书  
> **核心原则**：吸收 ShadowBroker 的信息治理与分析机制，不部署 ShadowBroker，不接实时外部 API，不进入交易链。  
> **新增关键依赖**：Z-Agent Runtime Governance Layer（Agent 入住、授权、审计、防篡改控制层）  
> **硬边界**：Research Only / Paper Only / No Broker / No Runtime / No Real Trade / No Production

---

## 0. 总裁决

v1.0 的问题：只吸收了 ShadowBroker 的 Event Hub / Physical Signal / NPA 框架，没有完整吸收更值钱的信息治理、源健康、层版本、增量查询、Agent 操作协议、分析标注、证据血缘和安全防泄漏机制。

v1.2 的裁决：

```text
ShadowBroker 不应该被直接部署进 Z-MATRIX。
但 ShadowBroker 的“信息治理与分析机制”必须被系统性吸收。
```

Z-G16 v1.2 的本质不是：

```text
接入 ShadowBroker 数据源
部署实时地图
做 OSINT 实时监控
```

而是：

```text
把 ShadowBroker 打磨出来的多源信息治理能力，
改造成 Z-MATRIX 的事件情报治理层。
```

最终目标：

```text
1. 多源事件治理能力
2. 数据源健康监控能力
3. 分层刷新与增量同步能力
4. 跨层假设生成能力
5. Agent 查询与操作协议
6. 研究标注与分析区能力
7. 证据归因与授权治理能力
8. 出站密钥防泄漏能力
9. 前端驾驶舱与后端 Agent 协同能力
```

# 第一部分：Agent 架构裁决

## 1.1 当前系统缺口

当前 Z-MATRIX 已经有安全硬门：

```text
real_trade_allowed=False
broker_order_allowed=False
runtime_enabled=False
production_allowed=False
paper_only=True
human_review_required=True
```

也已经有：

```text
ResearchDB Constitution
Experiment Ledger
Factor Registry
Promotion Pipeline
V4.0 Final Hardgates
RC1 审计链
```

但这些主要是系统级安全边界、研究平台治理骨架和模块准入规则，还不是完整的 Agent 入住空间。

因此，Z-MATRIX 在正式进入 LLM + Agent 后端自动运行、前端用户交互控制、自动报告生成之前，必须补一个独立硬层：

```text
Z-Agent Runtime Governance Layer
```

否则未来最大风险不是某个因子错，而是：

```text
Agent 自己发挥
Agent 篡改配置
Agent 绕过硬门
Agent 误写研究结论
Agent 污染 ResearchDB
Agent 把未验证结果升级为 READY
Agent 泄漏 API Key / 账户数据
Agent 直接改生产链
```

## 1.2 新增 P0 前置层

新增：

```text
Z-AGENT-0 Agent Runtime Governance Layer
```

职责：

```text
1. Agent 注册
2. Agent 权限声明
3. Agent 命令封装
4. Agent 工作区隔离
5. Agent 输出 Envelope
6. Agent 提案/审批/执行三段式
7. Agent 防篡改
8. Agent 密钥防泄漏
9. Agent 行为审计
10. Agent 前端动作队列
```

硬原则：

```text
Agent 永远不能直接改变系统状态。
Agent 只能提交 proposal。
Proposal 必须经过 Policy Gate。
高风险 proposal 必须进入 Human Approval。
执行后必须 Verify。
Verify 后才能 Commit。
Commit 后必须 Cloud Visibility Check。
```

# 第十部分：最终裁决

Z-G16 v1.2 必须和 Z-Agent Runtime Governance Layer 一起落地。

如果只做 Z-G16，而不做 Agent Governance，未来系统会出现：

```text
Agent 有能力，但没有边界。
Agent 会写文件，但没有审批。
Agent 会输出报告，但没有证据约束。
Agent 会操作前端，但没有动作协议。
Agent 会修改系统，但没有防篡改。
```

这不是智能化，是失控。

最终正确路径：

```text
先建 Agent 入住与防篡改层
再建 Z-G16 信息治理层
再建 NPA / Hypothesis / Annotation
最后才考虑是否真实接入 ShadowBroker 数据源
```

当前版本最终状态必须保持：

```text
STUB_ONLY
RESEARCH_ONLY
PAPER_ONLY
NO_PRODUCTION
NO_BROKER
NO_RUNTIME
NO_REAL_TRADE
NO_DIRECT_AGENT_MUTATION
```

这才是 Z-MATRIX 进入 Agent 时代前必须补齐的地基。
